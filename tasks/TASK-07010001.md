## 확정 모듈 경계

- `transactions`: 거래, 반복 거래와 영수증 연결
- `budgets`: 월간·카테고리 예산과 소진 조회
- `accounts`: 계좌, 잔액, 자산과 부채
- `analytics`: 기간 집계, 소비 추이와 지출 순위
- `auth`: 인증 주체와 접근 context 변환
- `shared`: 업무 의미가 없는 공통 오류, 식별자와 cross-cutting Port

## 의존 방향

```text
Controller / Presenter -> Application Use Case -> Domain
                                  |
                                  v
                             Port interface
                                  ^
                                  |
                  Prisma / HTTP / Queue Adapter
```

- Domain은 NestJS, Prisma, Redis, HTTP와 파일 시스템을 import하지 않는다.
- Application은 Domain과 Port만 참조하며 Adapter 구현을 import하지 않는다.
- Controller는 validation과 인증 context 변환 후 Use Case만 호출한다.
- Infrastructure Adapter는 Application Port를 구현하고 composition root에서 주입한다.
- 도메인 간 호출은 다른 모듈의 Infrastructure가 아니라 공개 Application interface를 사용한다.
- 순환 참조는 허용하지 않으며 공유를 이유로 업무 모델을 `shared`에 이동하지 않는다.

## 배치 규칙

- 공통 핵심은 `packages/domain/src/<module>`과 `packages/application/src/<module>`에 둔다.
- API interface와 Adapter 조립은 `apps/api/src/modules/<module>`에 둔다.
- 각 package는 public index/export만 외부에 공개하고 내부 경로 import를 금지한다.

## 검증 기준

- import boundary lint 또는 dependency graph 검사로 역방향·순환 의존을 차단한다.
- Domain unit test는 외부 resource 없이 실행한다.
- Application test는 Port fake를 사용하고 Adapter는 integration test로 검증한다.
