## 확정 기준

- 공통 Domain/Application과 Web은 Vitest, API/Worker와 Mobile은 Jest를 사용하며 한 workspace 안에서 runner를 혼용하지 않는다.
- 단위 테스트는 외부 자원을 fake Port로 대체하고 성공, 입력 거절과 경계값을 검증한다. 핵심 모듈의 line/branch/function/statement coverage는 각각 80% 이상으로 설정한다.
- API 통합 테스트는 Nest test application, Supertest와 격리된 PostgreSQL schema를 사용하고 테스트 종료 시 연결과 데이터를 정리한다.
- E2E는 Playwright로 거래 등록·조회, 예산 확인과 리포트 조회의 최소 사용자 흐름을 검증하며 임의 sleep을 사용하지 않는다.
- PR 파이프라인은 install, lint, typecheck, unit, integration, build, E2E 순서로 실행하고 어느 한 단계라도 실패하면 병합을 차단한다.
- 실패 E2E의 trace, screenshot과 video만 제한적으로 보관하고 artifact에 secret이나 개인정보가 포함되지 않게 한다.
- 상세 파일 위치, fixture와 assertion 규칙은 루트 `TESTS.md`를 단일 기준으로 사용한다.
