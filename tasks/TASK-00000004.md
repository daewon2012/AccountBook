1. Architecture 분해 결과를 기준으로 카테고리별 구현 순서를 정리한다.
2. 각 세부 TASK의 입력, 출력, 검증 기준을 정리한다.
3. 도메인 간 의존관계를 확인하고 작업 순서를 조정한다.
4. 구현 전 확인해야 할 공통 정책과 위험요소를 정리한다.

## 카테고리별 계획
### 거래기록
- 거래 도메인 모델과 저장 구조를 먼저 정의한다.
- 거래 CRUD를 구현한 뒤 반복 거래와 OCR을 확장한다.

### 예산관리
- 월/카테고리 예산을 먼저 만들고 봉투 예산과 저축 목표를 추가한다.

### 자산부채
- 계좌 모델과 잔액 집계를 먼저 구현하고 부채 추적을 연결한다.

### 자동화
- 규칙 DSL과 자동 분류를 먼저 만든 뒤 구독 탐지와 계좌 연동으로 확장한다.

### 분석리포트
- 집계 뷰 모델을 먼저 정의하고 대시보드, 내보내기, 이상지출을 순차 구현한다.

### 플랫폼
- 백업 스키마와 복원부터 만들고, 환율과 공동 가계부를 추가한다.
