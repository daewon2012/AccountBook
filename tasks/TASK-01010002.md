# TASK-01010002

## 상태
DONE

## 목적
거래 단건 관리 기능을 Web과 Mobile에서 공통 업무 규칙으로 제공하되 외부 자원 접근을 Adapter 뒤로 격리한다.

## 사용자 시나리오
사용자가 거래 단건 관리 기능을 사용할 때 Web과 Mobile이 동일한 서버 유스케이스와 업무 규칙을 통해 일관된 결과를 얻는다.

## 책임 구분

- 주 책임: 공통 Application + API Interface
- Common: 도메인 규칙, 유스케이스, Port, 공통 API 계약을 소유한다.
- Adapter/Infrastructure: PostgreSQL/Prisma, Redis/BullMQ, 파일 저장소 또는 외부 HTTP 연동을 Port 구현으로 제공한다.
- Web: Next.js 화면 상태, 폼 검증, 조회 캐시와 사용자 피드백을 담당한다.
- Mobile: Expo 화면 상태, 오프라인 입력 보존, 보안 저장소 및 기기 기능 연결을 담당한다.
- 공통 UI: 프레임워크 컴포넌트가 아니라 OpenAPI 타입, 표시용 DTO, 검증 가능한 순수 formatter만 공유한다.

## 구현 계획
1. 입력 Command/Query와 출력 DTO를 정의하고 Application Use Case에서 흐름을 조정한다.
2. 저장소, Clock, Queue, File Storage 또는 외부 HTTP가 필요하면 Port를 Application 경계에 정의한다.
3. NestJS Controller는 요청 검증과 인증 컨텍스트 변환만 수행하고 업무 규칙을 Use Case에 위임한다.
4. Web과 Mobile은 생성된 OpenAPI client를 사용하고 계산 및 상태 전이 규칙을 클라이언트에 복제하지 않는다.

## 예상 영향 파일

- packages/domain/src/transactions/**: Entity, Value Object, Policy, Domain Service
- packages/application/src/transactions/**: Use Case와 외부 자원 Port
- packages/contracts/src/transactions/**: 요청/응답 schema와 공유 타입
- apps/api/src/modules/transactions/**: Controller와 Infrastructure Adapter 조립
- apps/web/src/features/transactions/**: Web 전용 화면 상태와 API 연결
- apps/mobile/src/features/transactions/**: Mobile 전용 화면 상태와 API 연결

> 위 경로는 현재 src/가 비어 있어 제안한 경로다. TASK-07000001, TASK-07010001, TASK-07060001의 scaffold 결과에 맞춰 확정한다.

## 외부 Resource 경계

- Domain은 NestJS, Prisma, HTTP client, Redis, 파일 및 Expo API를 import하지 않는다.
- Application은 Port만 참조하며 트랜잭션 경계와 오류 의미를 정의한다.
- 실제 DB, Queue, Storage, 외부 API 및 플랫폼 API 접근은 Infrastructure 또는 플랫폼 Adapter가 구현한다.
- Web/Mobile은 REST/OpenAPI 계약으로 API를 호출하고 서버 업무 규칙을 재구현하지 않는다.

## 구현 결과

- `src/contracts/transactions/transaction-contract.ts`: Web과 Mobile이 공유할 등록·수정 요청, 거래 응답 및 안정적인 오류 코드/HTTP 상태 계약을 정의했다.
- `src/application/transactions/transaction-service.ts`: 거래 등록, 부분 수정, 삭제와 단건 조회 Use Case를 구현했다.
- `src/application/transactions/transaction-repository.ts`: 삭제 결과를 명시적으로 반환하는 `deleteById` Port를 추가했다.
- `src/infrastructure/transactions/in-memory-transaction-repository.ts`: 외부 자원 없이 동작하는 삭제 Adapter를 구현했다.
- 입력 오류(400), 미존재(404), 중복(409), 저장소 장애(503)를 `TransactionApplicationError`로 일관되게 변환한다.
- NestJS와 Prisma scaffold가 아직 준비되지 않아 HTTP Controller와 실제 DB 통합 테스트는 각 설치 및 Adapter 후속 TASK에서 수행한다.
