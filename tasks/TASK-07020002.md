## 확정 정책

- migration은 개발 검증, stage 백업, `prisma migrate deploy`, 애플리케이션 배포 순으로 실행하며 운영에서 `migrate dev`를 사용하지 않는다.
- 스키마 변경은 expand-and-contract 방식으로 호환 가능한 컬럼/테이블을 먼저 추가하고 데이터 이관과 구버전 제거를 별도 배포로 나눈다.
- 실패 시 애플리케이션을 직전 이미지로 되돌리는 것을 우선하며 파괴적 down migration 대신 검증된 forward fix를 사용한다.
- 운영 DB는 매일 전체 백업과 WAL 연속 보관을 적용한다. 기본 목표는 RPO 15분, RTO 4시간이며 서비스 등급 확정 후 조정한다.
- 백업 파일은 운영 DB와 다른 장애 영역에 암호화해 저장하고 접근 권한과 보존 기간을 운영 계정별로 제한한다.
- 분기마다 격리된 환경에 복원해 migration 상태, 행 수, 외래 키, 핵심 거래 조회와 체크섬을 검증하고 결과를 기록한다.
