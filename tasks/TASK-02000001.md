# TASK-02000001

## 상태
PLAN

## 목적

Next.js 웹 애플리케이션의 모든 업무 화면을 감싸는 공통 앱 셸과 반응형 내비게이션을 구현한다. 사용자가 현재 위치와 앱 상태를 보조 기술을 포함한 모든 환경에서 명확히 인식하도록 한다.

## 사용자 시나리오

- 데스크톱 사용자는 고정 사이드바에서 대시보드, 거래, 예산, 계좌·자산, 리포트와 설정으로 이동한다.
- 좁은 화면 사용자는 접근 가능한 메뉴를 열어 같은 목적지로 이동하고, 메뉴 선택 후 콘텐츠에 집중한다.
- 사용자는 어느 화면에서도 현재 위치를 확인하고 빠른 거래 등록으로 진입한다.
- 화면 전환 또는 데이터 요청 중에는 로딩 상태를, 실패 시에는 오류 내용과 재시도 수단을 인식한다.

## 책임과 경계

- 앱 셸은 레이아웃, 내비게이션 표시, 현재 경로 강조와 공통 상태 표현만 담당한다.
- 라우팅은 Next.js App Router를 사용하며 업무 화면은 각 기능 route가 소유한다.
- 서버 상태는 TanStack Query, 순수한 메뉴 열림 상태만 컴포넌트 state 또는 Zustand로 관리한다.
- 업무 규칙과 API 응답 계산을 앱 셸에 두지 않는다.
- 메뉴 정의는 하나의 타입 안전한 설정을 데스크톱과 모바일 표현이 함께 사용한다.

## 구현 계획

1. `apps/web` scaffold와 App Router 구조를 확인하고 공통 route group의 `layout.tsx`에 앱 셸을 연결한다.
2. 대시보드, 거래, 예산, 계좌·자산, 리포트와 설정의 label, href, icon 정보를 단일 내비게이션 모델로 정의한다.
3. 데스크톱 breakpoint에서는 좌측 사이드바, 좁은 화면에서는 상단 bar와 modal 또는 drawer 메뉴를 제공한다.
4. 현재 pathname을 기준으로 활성 항목에 시각 표시와 `aria-current="page"`를 함께 적용한다.
5. 본문으로 바로 이동하는 skip link, landmark(`header`, `nav`, `main`)와 의미 있는 페이지 제목 연결을 구성한다.
6. 메뉴 열기/닫기, Escape, 외부 영역 선택, route 이동 후 닫기와 focus 복원 동작을 구현한다.
7. 데스크톱 상단과 모바일 화면에서 빠른 거래 등록 링크를 항상 찾을 수 있게 제공한다.
8. route-level `loading.tsx`와 `error.tsx`를 구성하고 로딩 상태는 `aria-live` 또는 `role="status"`, 오류는 `role="alert"`와 재시도 버튼으로 표시한다.
9. 현재 기능 route가 아직 구현되지 않은 경우 링크 계약과 최소 placeholder 경계를 두되 업무 화면 구현을 이 TASK에 포함하지 않는다.

## 예상 영향 파일

- `apps/web/src/app/(app)/layout.tsx`: 인증 후 공통 앱 셸 조립
- `apps/web/src/app/(app)/loading.tsx`: 접근 가능한 route 로딩 상태
- `apps/web/src/app/(app)/error.tsx`: 오류 안내와 재시도 경계
- `apps/web/src/components/layout/app-shell.tsx`: 공통 레이아웃
- `apps/web/src/components/layout/desktop-sidebar.tsx`: 데스크톱 내비게이션
- `apps/web/src/components/layout/mobile-navigation.tsx`: 좁은 화면 내비게이션
- `apps/web/src/components/layout/navigation-items.ts`: 공유 메뉴 모델
- `apps/web/src/components/layout/*.test.tsx`: 상호작용과 접근성 단위 테스트

> 실제 경로와 alias는 TASK-09030000의 scaffold 결과를 우선하며, 동일 책임의 기존 파일이 있으면 새 구조를 중복 생성하지 않는다.

## 상태별 동작

- 현재 화면: 색상에만 의존하지 않는 강조와 `aria-current="page"`를 제공한다.
- 로딩: 레이아웃 이동을 줄이는 skeleton 또는 진행 상태와 읽을 수 있는 상태 문구를 제공한다.
- 오류: 사용자용 설명, 재시도 동작과 필요 시 안전한 기본 화면 이동을 제공한다.
- 메뉴 열림: 배경 콘텐츠의 잘못된 focus 진입을 막고 키보드 focus를 메뉴 안에서 관리한다.
- 빈 업무 데이터: 앱 셸이 아닌 각 기능 화면에서 처리한다.

## 테스트 계획

- 메뉴 모델의 모든 목적지가 데스크톱 및 모바일 내비게이션에 동일하게 표시되는지 Vitest로 검증한다.
- 현재 pathname에 해당하는 항목만 `aria-current="page"`인지 검증한다.
- 모바일 메뉴의 열기, Escape 닫기, route 선택 후 닫기와 trigger focus 복원을 검증한다.
- skip link, `nav` label, `main` landmark, 빠른 거래 등록 링크를 role과 accessible name으로 검증한다.
- 로딩 상태의 status announcement와 오류 경계의 alert 및 재시도 호출을 검증한다.
- viewport별 핵심 내비게이션과 키보드 이동을 Playwright smoke test 대상으로 등록한다.
- `pnpm --filter <web-package> lint`, `typecheck`, `test`와 production build를 통과시킨다.

## 완료 조건

- 데스크톱 사이드바와 좁은 화면 내비게이션이 동일한 목적지로 정상 이동한다.
- 빠른 거래 등록 진입점과 현재 화면 표시가 모든 지원 viewport에서 제공된다.
- 키보드와 보조 기술로 메뉴를 열고 이동하고 닫을 수 있다.
- 현재 화면, 로딩과 오류 상태가 시각적·비시각적으로 인식 가능하다.
- 앱 셸 컴포넌트 테스트와 관련 lint, typecheck 및 build가 통과한다.
