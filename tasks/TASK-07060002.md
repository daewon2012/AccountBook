## 상태 소유권

## API 연동 규칙

- 생성된 OpenAPI client를 감싼 Mobile API Adapter가 base URL, timeout, 인증 header와 오류 mapping을 담당한다.
- GET은 일시적 network 오류에 제한된 exponential backoff를 적용한다.
- mutation은 idempotency key가 있을 때만 자동 재전송하며 사용자 동작 하나에 key 하나를 유지한다.
- RFC 7807 `code`를 기준으로 validation, 인증 만료, conflict와 재시도 가능 오류를 구분한다.
- token 갱신은 동시에 한 요청만 수행하고 대기 요청을 재개하거나 모두 안전하게 실패시킨다.

## 오프라인과 충돌 복구

- 입력 초안은 사용자 확인 없이 서버 데이터로 간주하지 않는다.
- offline 저장 요청은 pending 상태와 생성 시각을 표시하고 재연결 후 명시적으로 동기화한다.
- 동일 idempotency key 재전송 결과는 하나의 거래로 취급한다.
- version/updatedAt 충돌은 자동 병합하지 않고 서버 값과 local 변경을 사용자에게 제시한다.
- 동기화 실패 시 초안을 보존하고 폐기·재시도 선택을 제공한다.

## 보안과 생명주기

- token, password와 개인정보를 AsyncStorage, URL, analytics 또는 log에 기록하지 않는다.
- 백그라운드 전환 시 민감 화면 snapshot 노출을 줄이고 메모리의 임시 인증 값을 정리한다.
- refresh token 실패 시 SecureStore 값을 제거하고 보호 route history를 로그인으로 교체한다.
- 앱 삭제·로그아웃 시 local draft 처리 여부를 사용자 정책에 따라 명확히 분리한다.

## 테스트 기준

- Network, SecureStore, Clock과 connectivity를 Jest fake로 대체한다.
- timeout, offline, token 만료, 단일 갱신, idempotent 재전송과 conflict 흐름을 검증한다.
- test log와 fixture에 실제 token 또는 개인정보가 포함되지 않는지 확인한다.
