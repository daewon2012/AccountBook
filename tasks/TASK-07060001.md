## 확정 폴더 구조

```text
apps/mobile/
├─ app/
│  ├─ _layout.tsx
│  ├─ (auth)/
│  └─ (app)/
│     ├─ _layout.tsx
│     ├─ (tabs)/
│     └─ transactions/new.tsx
└─ src/
   ├─ components/{ui,navigation,feedback}/
   ├─ features/{dashboard,transactions,budgets,accounts,reports,settings}/
   ├─ navigation/
   ├─ api/
   └─ adapters/{secure-storage,notifications,camera,files,network}/
```

- `app` route는 parameter 변환과 feature screen 조립만 수행한다.
- 업무별 화면, hook, presenter와 테스트는 `src/features/<feature>`에 둔다.
- 비업무 공통 UI만 `src/components/ui`, 앱 셸은 `components/navigation`에 둔다.
- Expo API 직접 호출은 `src/adapters`에만 허용한다.

## 내비게이션 규칙

- `(auth)`와 `(app)`을 분리하고 세션 확인 전 보호 route를 렌더링하지 않는다.
- 핵심 tab은 홈, 거래, 예산, 리포트, 더보기 순서로 고정한다.
- 거래 등록은 현재 tab 위 modal로 열고 완료·취소 후 호출 위치로 복귀한다.
- 계좌·자산과 설정은 더보기 stack에서 진입한다.
- 인증이 필요한 deep link는 목적지를 보존했다가 로그인 성공 후 한 번만 복귀한다.
- 인증 만료 시 민감 modal을 닫고 로그인으로 replace하여 보호 화면 history를 제거한다.
- 알림 payload는 route name과 검증 가능한 식별자만 포함하고 임의 URL을 실행하지 않는다.

## 의존 규칙

- `app -> features -> api/navigation/components` 방향만 허용한다.
- `features`끼리 내부 파일을 import하지 않고 공개 entry point 또는 navigation event를 사용한다.
- `components`와 `navigation`은 업무 feature를 import하지 않는다.
- Domain/Application package는 React Native와 Expo package를 import하지 않는다.
- TypeScript path alias와 lint boundary 규칙으로 역방향·순환 import를 차단한다.

## 검증 기준

- route parameter, deep link, back navigation과 인증 만료를 router test double로 검증한다.
- adapter는 Jest mock으로 대체하며 unit test에서 실제 기기 API를 호출하지 않는다.
