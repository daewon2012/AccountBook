- TASK-01 세부 계획 51개를 생성했다.

- 공통 UI 공유 범위는 OpenAPI 타입, 표시 DTO, 순수 formatter로 제한했다.

1. 거래, 계좌, 예산의 Domain 모델과 Application Port
2. Prisma Repository와 기본 NestJS REST API
3. Web/Mobile의 거래 및 계좌 기본 흐름
4. 반복 거래, 봉투 예산, 저축 목표와 부채

7. 백업/동기화, 다중 통화, 공유 지갑

## Architecture 결정 필요 사항

- 현재 src/가 비어 있으므로 apps/*와 packages/*의 실제 workspace 이름 및 경로를 scaffold 단계에서 확정해야 한다.
- API 계약의 원본을 NestJS OpenAPI schema로 둘지 독립 contract package로 둘지 결정해야 한다.
- Domain 이벤트, Application 트랜잭션, BullMQ 작업 간 일관성에 Outbox 패턴을 적용할지 결정해야 한다.
- Mobile 오프라인 저장소 제품과 충돌 해결 책임을 확정해야 한다.
- Web/Mobile 간 공유 가능한 formatter 및 schema의 의존성 허용 기준을 확정해야 한다.
