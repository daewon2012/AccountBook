## 상태
DONE

## 목표
핵심 테이블/인덱스 설계 초안을 작성한다.

## 계획
1. Prisma schema로 거래/예산/계좌/부채 모델을 정의한다.
2. 자주 조회되는 조건(날짜, 카테고리, 계좌)에 복합 인덱스를 설계한다.
3. 월간 리포트용 materialized view 후보를 도출한다.
4. EXPLAIN ANALYZE 기준으로 인덱스 검증 절차를 정의한다.

## 구현 후보
- Prisma Schema
- PostgreSQL B-Tree / Partial Index
- pg_stat_statements

## 완료 조건
- 거래/예산/계좌/부채 핵심 스키마가 정의된다.
- 조회 성능 기준 인덱스가 제안된다.

## 확정 설계

- 모든 원장 테이블은 `id`, `household_id`, `created_at`, `updated_at`을 가지며 금액은 최소 화폐 단위의 `BIGINT`로 저장한다.
- `transactions`는 유형, 금액, 발생일, 카테고리, 계좌, 메모를 저장하고 `(household_id, occurred_on DESC, id)`를 기본 목록 인덱스로 사용한다.
- 카테고리 및 계좌 필터는 각각 `(household_id, category_id, occurred_on DESC)`와 `(household_id, account_id, occurred_on DESC)` 복합 인덱스를 사용한다.
- `budgets`는 가구·월·카테고리 조합, `accounts`는 가구·이름 조합을 unique로 관리한다. 부채 계약과 상환 내역은 외래 키로 연결한다.
- 삭제 가능한 참조 데이터는 비활성 상태로 보존하고 원장 거래의 외래 키는 임의 cascade 삭제하지 않는다.
- 월간 집계는 초기에는 SQL 집계로 제공하고 실제 쿼리가 목표 응답시간을 넘을 때 materialized view를 도입한다.
- 주요 목록 쿼리는 운영과 유사한 데이터에서 `EXPLAIN (ANALYZE, BUFFERS)`로 검사하고 불필요한 sequential scan과 정렬 spill 여부를 기록한다.
