비동기 워커/스케줄러 운영 구조를 정의한다.

## 계획
1. BullMQ로 반복거래/알림/환율/리포트 큐를 분리한다.
2. Redis 기반 dedup key로 중복 실행을 방지한다.
3. 실패 재시도(backoff)와 DLQ 정책을 정의한다.
4. 워커 메트릭(성공률, 지연시간, 재시도율)을 수집한다.

## 완료 조건
- 반복거래/알림/환율/리포트 배치 실행 정책이 정의된다.
- 재시도/중복 방지/보상 처리 규칙이 정의된다.

## 확정 정책

- `recurring-transactions`, `notifications`, `exchange-rates`, `reports`를 별도 BullMQ queue로 분리하고 queue별 concurrency와 rate limit을 설정한다.
- producer는 업무 식별자와 기준 시점을 조합한 결정적 job ID를 사용하며 consumer도 원장 DB의 unique key로 멱등성을 보장한다.
- 일시 오류는 지수 backoff와 jitter를 적용해 최대 5회 재시도하고 validation 및 권한 오류는 재시도하지 않는다.
- 최종 실패 job은 원 queue별 DLQ에 원인 code와 correlation ID만 기록하며 개인정보와 secret은 payload 및 log에서 제외한다.
- 부분 반영 가능성이 있는 작업은 DB transaction으로 보호하고 외부 전송 후 실패한 작업은 상태 기반 재처리 또는 명시적 보상 작업을 사용한다.
- 성공률, 처리 지연, 대기 job, 재시도와 DLQ 수를 metric으로 수집하고 scheduler는 Redis lock과 만료시간으로 단일 실행을 보장한다.
