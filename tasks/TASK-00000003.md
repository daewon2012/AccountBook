## Architecture Design

### 0. Target Stack
- Web: Next.js + React + TypeScript
- Mobile: React Native + Expo + TypeScript
- Server: NestJS + TypeScript
- Database: PostgreSQL
- Proxy: Nginx
- ORM: Prisma
- Cache/Queue: Redis
- File Storage: S3-compatible object storage
- API Style: REST 중심, 필요 시 내부 이벤트/비동기 작업 분리

### 0-1. Development Languages
- TypeScript를 웹, 모바일, 서버와 공유 API 계약의 공통 개발 언어로 사용한다.
- SQL은 데이터 모델과 집계 쿼리에서 직접 다룬다.
- 인프라 스크립트는 Bash 또는 PowerShell로 보조한다.

### 0-2. Deployment Topology
- Browser -> Nginx -> Next.js(Web) / NestJS(API) -> PostgreSQL, Redis, Object Storage
- Mobile App -> Nginx -> NestJS(API) -> PostgreSQL, Redis, Object Storage
- Nginx는 TLS 종료와 정적 자산 캐싱, API 라우팅을 담당한다.
- 서버는 stateless하게 유지하고 세션/캐시/큐는 외부 저장소로 분리한다.

### 1. Domain Layer
- 거래, 예산, 자산, 부채, 자동화, 분석, 플랫폼을 독립 도메인으로 분리한다.
- 각 도메인은 엔티티, 값 객체, 도메인 규칙을 독립적으로 가진다.

### 2. Application Layer
- 도메인별 유스케이스를 분리한다.
- 거래 생성/조회, 예산 계산, 자산 집계, 자동 분류, 리포트 생성 같은 흐름을 조립한다.

### 3. Interface Layer
- 사용자 화면 또는 API에서 들어오는 요청을 유스케이스로 전달한다.
- 입력 검증, 응답 매핑, 오류 처리를 담당한다.

### 4. Infrastructure Layer
- 저장소, 파일, 외부 연동, 스케줄러, 환율/알림 같은 주변 시스템을 구현한다.
- 교체 가능한 어댑터 구조를 사용한다.
- PostgreSQL은 거래/예산/계좌/리포트의 단일 진실 원천으로 사용한다.
- Redis는 캐시, 작업 큐, 중복 방지 키에 사용한다.
- Nginx는 리버스 프록시와 정적 파일 서빙을 담당한다.
- S3 호환 스토리지는 영수증 이미지와 백업 파일에 사용한다.

### 4-1. API and Service Boundaries
- Web은 화면 렌더링과 입력 검증을 담당한다.
- Mobile은 iOS/Android 화면, 기기 기능, 보안 저장소와 푸시 알림을 담당한다.
- Server는 인증, 유스케이스 조립, 도메인 규칙 실행을 담당한다.
- Database는 정합성 보장과 조회 성능 최적화를 담당한다.
- Proxy는 외부 트래픽 제어, TLS, 압축, 캐시를 담당한다.
- Background worker는 반복 거래, 알림, 환율 갱신, 리포트 생성 같은 비동기 작업을 담당한다.

### 4-2. Data Model Concerns
- PostgreSQL을 영속 데이터의 단일 진실 원천으로 두며 Redis 유실이 원장 데이터 유실로 이어지지 않게 한다.
- 금액은 통화 코드와 최소 화폐 단위 정수 또는 정밀 Decimal로 저장하고 시간은 UTC로 저장한다.
- 거래는 append-friendly 구조를 유지하고 수정 이력 추적을 고려한다.
- 예산과 집계는 기간 기준 스냅샷 또는 계산 뷰로 분리한다.
- 계좌/부채/공동지갑은 권한과 소유권을 분리해 관리한다.

### 4-3. Quality and Ops
- 단위 테스트, 통합 테스트, E2E 테스트를 계층별로 분리한다.
- 로깅, 감사 로그, 모니터링, 장애 추적을 공통 운영 정책으로 둔다.
- 마이그레이션과 백업/복원 절차를 배포 체크리스트에 포함한다.

### 5. Cross-cutting Concerns
- 인증/권한, 로깅, 감사 로그, 예외 처리, 테스트 전략을 공통 정책으로 둔다.
- correlation ID를 Proxy, API, Worker에 전달하고 토큰, 비밀번호, 영수증 원문은 로그에서 제외한다.
- DB 변경과 Queue 발행의 정합성은 transactional outbox와 멱등성 키로 보장한다.
