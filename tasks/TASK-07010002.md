## 확정 API 계약

- base path는 `/api/v1`, resource 이름은 복수형 kebab-case를 사용한다.
- JSON field는 camelCase, 날짜는 ISO 8601, 금액은 통화 최소 단위의 정수로 전달한다.
- 목록 요청은 명시적인 cursor 또는 page 계약을 사용하며 정렬 기준을 응답에 반영한다.
- 요청 DTO validation 실패는 controller 경계에서 처리하고 업무 오류는 Application 오류로 변환한다.
- Swagger/OpenAPI 문서를 서버에서 생성하고 Web/Mobile client type의 단일 기준으로 사용한다.

## 오류 형식

```json
{
  "type": "https://accountbook.example/problems/validation-error",
  "title": "입력값을 확인해 주세요",
  "status": 400,
  "code": "VALIDATION_ERROR",
  "detail": "요청에 유효하지 않은 값이 있습니다.",
  "instance": "/api/v1/transactions",
  "fieldErrors": { "amount": ["금액은 0보다 커야 합니다."] },
  "traceId": "request-correlation-id"
}
```

- 공통 code는 `VALIDATION_ERROR`, `UNAUTHENTICATED`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `RATE_LIMITED`, `INTERNAL_ERROR`를 사용한다.
- 내부 exception, stack, SQL과 개인정보는 응답에 노출하지 않는다.
- `traceId`는 지원·관측용이며 인증정보를 포함하지 않는다.
- Axios/Mobile client는 HTTP status가 아니라 `code`를 기준으로 복구 UI를 선택한다.

## 검증 기준

- OpenAPI schema와 생성 client type의 drift를 contract test로 차단한다.
- 정상 응답, validation, 인증·권한, not-found와 conflict 응답 schema를 통합 테스트한다.
