# TASK-01040001

## 상태
PLAN

## 목적
분류 규칙 DSL 기능을 Web과 Mobile에서 공통 업무 규칙으로 제공하되 외부 자원 접근을 Adapter 뒤로 격리한다.

## 사용자 시나리오
사용자가 분류 규칙 DSL 기능을 사용할 때 Web과 Mobile이 동일한 서버 유스케이스와 업무 규칙을 통해 일관된 결과를 얻는다.

## 책임 구분

- 주 책임: 공통 핵심(Domain/Application)
- Common: 도메인 규칙, 유스케이스, Port, 공통 API 계약을 소유한다.
- Adapter/Infrastructure: PostgreSQL/Prisma, Redis/BullMQ, 파일 저장소 또는 외부 HTTP 연동을 Port 구현으로 제공한다.
- Web: Next.js 화면 상태, 폼 검증, 조회 캐시와 사용자 피드백을 담당한다.
- Mobile: Expo 화면 상태, 오프라인 입력 보존, 보안 저장소 및 기기 기능 연결을 담당한다.
- 공통 UI: 프레임워크 컴포넌트가 아니라 OpenAPI 타입, 표시용 DTO, 검증 가능한 순수 formatter만 공유한다.

## 구현 계획
1. 프레임워크 의존성이 없는 Entity, Value Object, Policy 또는 Domain Service로 업무 규칙을 정의한다.
2. 저장소, Clock, Queue, File Storage 또는 외부 HTTP가 필요하면 Port를 Application 경계에 정의한다.
3. NestJS Controller는 요청 검증과 인증 컨텍스트 변환만 수행하고 업무 규칙을 Use Case에 위임한다.
4. Web과 Mobile은 생성된 OpenAPI client를 사용하고 계산 및 상태 전이 규칙을 클라이언트에 복제하지 않는다.

## 예상 영향 파일

- packages/domain/src/classification/**: Entity, Value Object, Policy, Domain Service
- packages/application/src/classification/**: Use Case와 외부 자원 Port
- packages/contracts/src/classification/**: 요청/응답 schema와 공유 타입
- apps/api/src/modules/classification/**: Controller와 Infrastructure Adapter 조립
- apps/web/src/features/classification/**: Web 전용 화면 상태와 API 연결
- apps/mobile/src/features/classification/**: Mobile 전용 화면 상태와 API 연결

> 위 경로는 현재 src/가 비어 있어 제안한 경로다. TASK-07000001, TASK-07010001, TASK-07060001의 scaffold 결과에 맞춰 확정한다.

## 외부 Resource 경계

- Domain은 NestJS, Prisma, HTTP client, Redis, 파일 및 Expo API를 import하지 않는다.
- Application은 Port만 참조하며 트랜잭션 경계와 오류 의미를 정의한다.
- 실제 DB, Queue, Storage, 외부 API 및 플랫폼 API 접근은 Infrastructure 또는 플랫폼 Adapter가 구현한다.
- Web/Mobile은 REST/OpenAPI 계약으로 API를 호출하고 서버 업무 규칙을 재구현하지 않는다.

## 완료 조건
- 키워드, 가맹점, 정규식 규칙 타입을 정의한다.
- 규칙 충돌 시 우선순위 정책을 정의한다.
- Common 규칙을 Web과 Mobile이 같은 API 계약으로 사용한다.
- 외부 자원 접근이 Port/Adapter 경계를 위반하지 않는다.

## 테스트 계획

- API integration: 상태 코드, 응답 schema, validation 및 권한 실패를 검증한다.
- 관련 workspace의 lint와 typecheck를 통과한다.
